# Motion 元素编辑器：本地首版产品方案

日期：2026-10-28。状态：产品范围与独立技术评审已通过本地原型准入，代码与主要交互已实现；验收记录见第 11 节。此状态不代表发布验收通过。

依据：[Figma Motion / Jitter 实操调研](./figma-jitter-editor-scope-20261028.md)。沿用已有 Motion 播放、时间定位、范围标注与修改对照能力。本方案新增可信的元素和入场动画直接编辑。

## 1. 产品决定

Open Design 的 Motion 编辑器服务于“生成之后快速改到满意”。默认以元素和动画片段组织操作：用户选中标题、图片或形状，直接改内容、外观或入场节奏；复杂的构图、风格和编排调整仍通过 AI 完成。

本地首版先验证一条完整路径：**选择元素 → 调整外观或入场 → 播放检查 → 保存 → 撤销 / 重做 → 重开继续编辑**。它不是专业剪辑软件的缩小版，也不承诺能把任意生成 HTML 反解成可编辑工程。

本轮实现范围限定为明确支持的单场景作品。用户原来的作品继续保留，不自动转换、不重写。受控作品中的对象和动画由同一份数据驱动；缺少可靠编辑数据的作品继续使用播放器与定向 AI 修改。

## 2. 用户、问题与完成标准

主要用户是通过提示词制作产品介绍、品牌宣传、社媒短片和文字动画的人。他们知道希望改什么，但通常不熟悉关键帧与曲线编辑。

优先解决四类任务：

1. 把标题换一句话，调整字号、颜色和位置，同时保留原有动画。
2. 让产品图晚出现 0.3 秒，入场更快或更柔和。
3. 让三个卖点按确定顺序依次出现，而不是反复描述节奏。
4. 修改后发现不满意，可靠回到上一步，刷新后仍可继续编辑。

首版成功标准不是控件数量，而是上述支持范围内的改动能确定性完成，用户能看出是否保存，失败时不丢原稿。新增高级关键帧、复杂特效与素材轨道不作为本轮完成条件。

## 3. 启用条件与能力边界

| 产物 | 用户看到什么 | 可以做什么 |
| --- | --- | --- |
| Motion 任务，且识别为支持的受控单场景作品 | “编辑动效”入口，元素列表、外观 / 动画面板、动画片段时间轴 | 本方案的直接编辑与保存恢复 |
| Motion 任务，普通生成 HTML 或不支持的动画实现 | 现有 Motion 播放器与标注能力；说明该作品暂不支持直接编辑 | 定位对象 / 时间范围后交给 AI 修改 |
| Motion 的 MP4 成品 | 视频播放与定位；有对应可编辑源时提供返回入口 | 不把成品里的标题、Logo 伪装为独立图层 |
| 普通网页、PPT、交互原型 | 现有预览 | 不展示 Motion 编辑器 |

是否开放字段由工程验证结果决定。存在 DOM 节点或 `data-od-id` 本身不是支持直接编辑的证据。受控作品被 AI 或外部工具改成不再支持的格式后，应关闭直接编辑并说明原因，保留当前文件和 AI 路径。

## 4. 首版功能范围

| 能力 | 本轮深度 | 明确边界 |
| --- | --- | --- |
| 播放与定位 | 复用播放暂停、逐帧、时间输入、拖动播放头；可查看整体与入场过程 | 时间单位和 FPS 清楚；输入精度不等于已证明导出精度 |
| 元素组织 | 文本、图片、基础形状；显示名称和类型；画布、元素列表、动画片段选中联动 | 单场景、已有元素；不首发自由绘图、任意 DOM 层级编辑 |
| 文本 | 文案、字号、颜色；保留换行和入场动画 | 不首发富文本、逐字或按词拆分、字体资源管理 |
| 基础外观 | 位置、大小、旋转、不透明度；形状颜色；图片在既有容器中展示 | 字段按对象类型出现；复杂 SVG、滤镜、遮罩和路径形变不开放 |
| 入场动画 | 淡入、位移入场、缩放入场等小集合；开始时间、时长、少量缓动预设 | 每个元素一个受控入场片段；不首发退场与多段属性叠加 |
| 片段编辑 | 整段拖动改开始时间，边缘拖动改时长；精确数值输入校准 | 松手形成一次操作；越界不静默截断；Esc 取消拖动 |
| 多选错峰 | 同一场景内多选入场动画，按明确顺序与间隔排列；一次保存和撤销 | 显示顺序；不首发嵌套组、跨场景联动或自动对拍 |
| 保存与恢复 | 明确未保存 / 保存中 / 已保存 / 失败状态；撤销、重做；刷新保留已保存结果 | 撤销当前编辑会话；若要跨会话恢复，使用既有文件版本能力，不能暗示无限历史 |
| AI 修改 | 继续使用已有定向标注和会话入口；不支持直接编辑时有可达入口 | 不新增 Agent 编排；AI 修改完成后重新检查可编辑能力 |
| 导出 | 沿用现有导出链路，编辑结果与播放使用同一作品源 | 本轮需验证同一源和关键时刻画面；未验证导出不得写“导出一致已通过” |

图片仅支持既有项目内、可验证的相对路径资源；不新增上传和远程 URL 接入。图片替换仍须确认资源存在性、路径约束和导出可达性；未闭环时保留静态展示和外观编辑，不提供虚假的“替换成功”。首版不以缺少图片替换而阻塞文本和形状的动画纵切验收。

## 5. 界面与交互

进入 Motion 作品仍默认可播放。用户进入编辑后，形成一个专注工作区：左侧元素，中央画布，右侧属性，底部时间轴。继续采用 Open Design 字体、灰阶与蓝色主色。

- 左侧列出当前场景元素，名称尽量对应内容；过长名称截断并可查看完整内容。可从列表选择被遮挡或尚未入场的元素。
- 中央画布保持宽高比并适配剩余空间。选中框与作品内容区分，不进入导出。本版选中对象会将播放头定位到其入场结束，便于查看完整外观；不增加容易与动画状态混淆的第二套静态预览模式。
- 右侧分“外观 / 动画”。外观表示基础状态，动画表示入场片段，不能因为改字意外创建关键帧。未选中时显示简短操作指引。
- 底部统一放播放与时间轴。每行对应元素，入场片段标明动作；播放头贯穿轨道。保留紧凑高度，让画布有足够空间，长列表内部滚动。
- AI 沿用当前会话或按需打开的面板，不再常驻一整列新聊天占用画布。
- 在 1280×720 和 1440×900 下检查布局；本版保持三栏最小可用宽度，更窄空间内部滚动；可折叠面板后置，不宣称移动端适配完成。

时间轴中对象存在区间与入场片段分开理解。标题可以持续存在 5 秒，其中前 0.6 秒淡入；动画片段的长度是 0.6 秒，不能将其标为“标题只存在 0.6 秒”。本轮不制造视频、音频、字幕空轨，也不把整份 HTML 合成误称为一段可剪切的视频素材。

数值输入应允许用户完成编辑再提交，避免输入 `0.` 等中间状态被立刻改写。文本与属性草稿经过约 180ms 停顿后调用只读预览接口，不写文件；“应用”才保存。拖动期间显示候选起点 / 时长，松手提交一次；Esc 或越界取消整次拖动。键盘输入文字时，Space、方向键和撤销键由输入控件优先处理。

## 6. 关键路径

### 改标题

选择标题 → “外观”中改文案与字号 → 画布显示候选结果 → 提交并保存 → 播放原入场动画。撤销一次恢复这次修改；重做恢复新值。刷新后显示已保存的新文案，不被初始化脚本覆盖。

### 调整产品入场

选择产品图的入场片段 → 整段向右移动 0.3 秒 → 输入时长 0.6 秒 → 选择“柔和”缓动 → 从入场之前播放检查 → 保存。拖动和精确输入改变同一数据，不应出现画面已变、重开后又变回去。

### 三个卖点错峰

按希望的顺序多选三个入场片段 → 查看顺序编号 → 输入间隔 0.12 秒 → 一次应用并播放检查。只修改开始时间，保留各自时长、文案和缓动。一旦任何片段越过场景末尾，整组不提交，并提示缩短间隔或改变起点；首版不自动延长场景。

### 当前作品不能直接编辑

继续播放 → 定位时间或对象 → 返回原预览，点击“标注并修改” → 沿用已有带截图、目标与时间的修改流程。不能先允许拖动，再在用户不知情时把操作变成一次模型生成。

## 7. 保存、冲突与失败

| 状态 / 事件 | 要求 |
| --- | --- |
| 拖动或数值尚未提交 | 标记为候选状态；取消恢复当前已保存值 |
| 正在保存 | 防止重复提交同一操作，禁用冲突写入；仍可看到当前画面与保存状态 |
| 保存成功 | 以服务端返回的新版本为准更新状态；不能只因前端变化就显示已保存 |
| 保存失败 / 断网 | 保留可识别的未保存状态，提供重试或放弃；不覆盖原文件 |
| AI / 外部工具已修改文件 | 拒绝旧版本写入；提示重新载入，不能静默覆盖新内容 |
| 旧对象身份失效或字段不可编辑 | 不写入其他对象；重新读取能力，必要时转 AI 修改 |
| 错峰或多字段提交含非法值 | 整次拒绝，指出问题；不能部分成功 |
| 页面刷新 | 重新读取保存结果；明确当前编辑会话的撤销 / 重做记录已清空，保存的源文件与版本仍保留 |
| AI 正在修改同一作品 | 直接编辑暂不可提交；AI 完成后重新载入版本与能力 |

手动修改与 AI 修改必须以同一文件为当前事实。首版不建设独立于产物源的另一套编辑器存档。

## 8. 工程评审的产品约束

以下约束是本轮实现与验收的前提，评审通过不代替代码和运行验证：

1. 受控作品中的唯一对象 ID、基础属性和入场参数可以确定性生成现有 GSAP 主时间轴，预览与导出消费同一数据。
2. 编辑器能证明作品仍满足受控格式，而非仅看到一个声明就信任可编辑性；不执行任意脚本来猜测编辑语义。
3. 服务端对当前源版本、对象身份、字段类型、数值范围和时间边界进行校验。提交以最新源为基准，提供版本冲突保护。
4. 文案、外观、时间和整组错峰可形成完整操作，失败时不留下半次修改；撤销 / 重做同样校验当前版本。
5. 新的读取与编辑能力通过统一 HTTP 契约供 UI 和 `od` CLI 使用；CLI 支持机器读取和文件输入。纯视觉布局、播放头交互不需要伪造 CLI 对应控件。
6. 工程没有可靠证明的能力不出现在可用控件中，且不得为了支持首版强制转换已有作品。

评审若发现当前保存、运行时或版本链路不满足这些前提，先缩小支持格式或提交范围，不能以增加确认弹窗代替可靠写回。

### 技术评审记录

2026-10-28 独立工程评审结论：**有条件通过受控单场景纵切，不批准任意 HTML 全量直接编辑。**

- 支持一个场景、每个对象一个入场动画。文本和形状为核心验收对象，图像遵循本节的既有项目资源限制。
- 使用带版本的固定渲染器，将作品数据生成已有 GSAP 主时间轴，并接入 `window.__timelines`；复用现有播放与导出，不新建动画引擎。
- 未知渲染器版本、生成后被外部改写的源文件不能继续套用旧编辑参数；重新识别，不满足格式时降级到原播放器与 AI 修改。
- 服务端在文件版本锁内核验源 SHA、项目是否正在编辑，写入前复读，写入后确认。出现冲突拒绝覆盖；不承诺能对所有绕过服务端的操作系统级外部写入提供绝对原子性。
- 撤销 / 重做以当前编辑会话为边界，刷新清空会话栈；作品源与文件版本持久保存。

这些条件必须在实现中落地，并通过第 9 节对应验收项后，才能称本地首版可用。新增的完整源、依赖、版本和请求串行校验已落地；独立复审原 4 项 P1 阻塞均关闭。剩余片尾循环问题已改为播放器内部处理，运行时回归通过，避免依赖宿主稀疏时间上报。

## 9. 验收清单

本地验收使用新建隔离示例，不覆盖前期研究与评测产物。主要浏览器样例包含中文、换行文本、基础形状和 10 个不同入场起点的对象。图片只纳入格式支持集，本轮未实测图片替换或复杂素材，不将其记为通过。

| 验收任务 | 通过条件 |
| --- | --- |
| 改文字与字号 | 当前显示、播放后、刷新后都一致；原入场保留；撤销与重做正确 |
| 修改位置 / 大小 / 不透明度 | 控件、选中框与画面一致；目标外的元素保持原值 |
| 拖动片段并数值校准 | 起点与时长可回读，播放从新时间发生；一次拖动只形成一次历史操作 |
| 切换缓动 | 中间过程实际变化，首尾状态仍正确；不能只检查静态截图 |
| 多选错峰 | 顺序与间隔正确；整组一步撤销；非法越界不产生部分保存 |
| 当前版本冲突 | 使用旧版本提交被拒绝，较新的文件内容未被覆盖 |
| 不支持的源 | 无直接编辑控件或明确不可用；现有播放与 AI 修改仍可达 |
| Motion 范围控制 | 普通网页、PPT、交互原型不出现编辑器 |
| 预览 / 导出 | 同一已保存版本，检查起点、中间、终点画面；若无法完成导出验证，单列为交付限制 |
| 小屏与输入 | 两档桌面尺寸可操作；长名称、长文案可用；输入时不误触播放器快捷键 |

本地交付须附可访问入口、实现支持集、实际通过项与未完成项。测试通过不替代浏览器中的编辑和保存重开证据。本轮不直接发布、提交 PR 或修改生产状态。

## 10. 后续范围与量化

第二阶段再考虑有限属性关键帧、自定义曲线、退场与多段动画、场景复制重排、真实音频 / 字幕编辑、资源替换管理。完整 NLE、3D、速度图、表达式、追踪、抠像、专业调色不属于当前路线。

首版先报告工程事实：支持格式、通过的编辑任务、保存重开与撤销结果、正确拒绝的冲突 / 非法输入、不支持案例的降级结果。受控示例成功不代表任意生成作品都可编辑。

后续用户对照沿用相同素材、相同目标和预先固定的达标标准，分别记录旧提示词流程与新编辑流程的首次达标率、修改轮次、从开始到可接受结果的耗时和误改率。直接编辑覆盖率单独统计，不能排除不支持作品后宣称全量成功率。此次不预先填写效率提升百分比。


## 11. 本地实现与验收记录

### 实现深度

- 分支：`codex/motion-review-20261025`，基线 `3fbd6358f038fe8715fe93298fd51b3911334597` 加本次及此前任务的本地修改；未提交 PR、合并或发布。
- 本地样例：`motion-object-editor-20261028`，会话 `91050b27-602a-44a9-bedd-108d3d41ea4e`。这是人工构造的受控验收作品，不是本轮模型生成质量样本，也没有自动转换旧 ECOTREE 源文件。
- 模型格式：版本 1 JSON，单场景、最多 64 个对象、每对象一个入场片段。文本、位置、尺寸、旋转、不透明度、颜色、入场起点/时长/预设/缓动可编辑；字体选择、图片替换、多场景和高级关键帧未实现。
- 交互：对象/画布/片段选中联动；显式“外观 / 动画”；先预览后应用；片段拖动和右边缘调时长；Shift 顺序多选、同组平移、错峰；会话撤销重做；播放器内部区间循环。
- 入口：Motion 任务的受控 HTML 显示“编辑动效”。普通任务不展示；自由生成 HTML 保留原播放器与 AI 标注路径。生成策略尚未默认产出这个受控格式，不能据此承诺现有所有 Motion 都可直接编辑。
- 后端：`/motion/editor/read`、`/preview`、`/save`，CLI `od motion inspect/preview/edit` 使用相同接口；候选预览不落盘。固定渲染器输出源码与当前文件完全相符才可直接编辑，同时核验同目录 GSAP 依赖。新源超过 1 MiB 在写前拒绝。
- 并发：保存进入已有项目变更队列及文件版本锁，检查 AI busy、源 SHA、写前复读和写后/历史确认；不承诺绕过服务端的外部进程写入绝对原子。未确认的写后状态要求重新载入，不盲目回滚。

### 已实际操作的主路径

1. 主标题从 `Make every / move count.` 改成 `Make motion / feel right.`。只读候选预览显示新文案时，CLI 仍读到磁盘原文；点击应用后保存。撤销恢复原文，重做恢复新文案。
