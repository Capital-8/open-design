# Motion 场景与内容轨首版

日期：2026-10-26。基线：`ba308a9da3c6df14e669b31250a8873a2e8aabbc`。阶段：需求评审 → 技术评审 → 本地实现与验收；不提交 PR、合并或发布。

## 用户问题与产品决定

现在时间轴只表达完整动效与批注。用户要修改“第三幕标题”或“这一句旁白”时，仍需从画面反复寻找、描述目标。调研支持把真实结构暴露给用户，选择结果成为 AI 修改上下文。参考及证据边界见 [编辑工作台竞品核查](./editor-competitive-research.md)；本次补查的 Kario [可编辑工程](https://www.karioai.com/ai-motion-graphics-generator)、[旁白与重排](https://www.karioai.com/ai-explainer-video-generator) 与 Jitter [选择上下文](https://help.jitter.video/en/articles/15656969-animate-with-ai-superagents) 支持这一选择。官方声明不等于竞品编辑效果实测。

本版做“可定位、可选择、可交给 AI 修改”的轻量分轨。场景为主，关键文字按场景展开，声音和字幕只展示可靠声明的内容。当前 ECOTREE 声明了五幕，只是验收样例，不把五幕写死。

## 需求与验收

| 编号 | 本版行为 | 验收与边界 |
| --- | --- | --- |
| R1 | 时间轴增加真实场景段，显示名称、区间与当前场景；保留画面缩略图、精确时间、逐帧和批注 | 源声明 N 幕就显示 N 幕；无有效声明回退完整动效。不能凭截图或模型猜分镜。 |
| R2 | 点击场景确认暂停并定位；当前播放位置所在场景同步高亮 | 不建第二套时钟；选中发生在定位 ACK 后，失败保留已确认状态。切源、定位或绘制/保存处理中禁止并发切换；已有标注先走下述草稿规则，再退出旧锁定并定位。 |
| R3 | 当前场景显示关键文字对象列表，选中后可“标注并修改” | 标题与明确标识的关键文字优先；不枚举全部 SVG/DOM。没有可靠入退场时间时，仅标为场景内对象，不画假的文字时长。 |
| R4 | “标注并修改”复用当前时刻截图、元素/场景目标、评论草稿和发送聊天链路 | 用户能检查目标、填写要求、保存或发送。切换目标不得丢未保存草稿；来源变化后不能把旧对象附到新作品。执行前等待当前暂停/锁定确认。 |
| R5 | 有可靠资源与时间信息时展示声音/字幕内容；没有则不显示空轨 | 区分声音与画面文字，不把标题当字幕。来源不明或未声明时间的资源不画时间片段，不伪造波形。资源不可定位到画面元素时只提供时间定位与场景批注入口。 |
| R6 | CLI 可以读取与 UI 相同的场景/内容结构；已有评论 CLI 继续承接反馈 | 新增结构读取通过同一 HTTP API 和 contracts DTO；支持 JSON。评论长要求复用现有 `--prompt-file`。不增加 UI 专属持久化。 |
| R7 | 默认紧凑，场景内对象按需展示，窄栏可用 | 画布与 dock 占位使用同一尺寸值；内容列表可横向滚动或折叠，不遮住画面、播放或批注。 |

场景点击的定位点取场景中点，避开常见的入场空帧；当前时刻已在场景内则保留当前时刻并暂停。用户仍可通过标尺和时间输入精确选择任意时刻。标题在该时刻不可见时提示改选时刻，不伪造选择框。

**切换规则**：有未保存草稿时，场景/对象切换先走现有放弃保护（第一次选择只显示提醒，重复选择才确认放弃，继续编辑会撤销确认状态）；未确认时草稿、选区和播放位置不变。确认后退出旧标注锁定，再暂停/定位/选新目标。来源变化立即使旧结构与选择失效，但不主动删除未发送草稿；旧草稿禁止按新来源提交，用户仍可复制要求后重新选择。

本版不开放拖动场景边界、重新排序、音量编辑、字幕改写、直接改字或关键帧；这些操作需要写回工程、撤销与导出一致性。当前展示是定位/选择入口，不显示裁剪手柄。复杂修改继续交给现有 Agent，不新增多 Agent 产品运行流程。

## 关键用户路径

1. ECOTREE 打开后看到五个场景及真实缩略图；选择第三幕，暂停定位至 6.5 秒，看到该幕标题。
2. 选中标题并进入已有标注编辑器，目标指向真实 h2；填写要求后可保存/发送到当前对话，时间、来源、截图与对象保持一致。
3. 有草稿时换场景/对象保留现有防丢流程；取消不切换。模型修改或文件切换后清除过期结构与选中目标。
4. 无场景的 canonical Motion 仍能播放、定位与批注；带有效声音/字幕声明的隔离样例可显示对应内容，无声明不显示。
5. CLI 读取与 UI 一致的结构。非法路径、旧来源、异常/不完整 HTML 不执行脚本、不泄漏项目外文件，错误/回退行为清楚。

## 效果与证据口径

本次证明结构准确、选择与反馈链路可用，以及原播放/批注无回归。记录实际操作、截图与源码/输入证据。真实模型链路最多使用独立示例副本的一次窄范围修改；既有对照实验与原始作品不重跑、不覆盖。若本版只验证发送前上下文，则明确说明未进行模型效果验证。

首次成功率、修改轮次和耗时改善需要可比样本，不能用多了轨道或单次成功宣称提高。后续用户对照重点测“找到目标 → 提交准确要求”的耗时与误选率。

## 技术方案（已通过评审）

### 静态结构读取与双轨

- contracts 增加纯 DTO 与当前预览同算法的来源指纹函数：根作品尺寸/时长、场景、文字对象、声音、字幕、软性 warnings。指纹是来源一致性标识，不是安全校验或可恢复历史版本。
- daemon 用已有 Cheerio 静态解析，不执行作者脚本、不取外部资源、不递归读取 composition。只认 canonical Motion 根；场景使用根内明确声明 start/duration 的 section 或子 composition；关键文字使用场景内语义标题与显式文字标识。重叠允许，播放器时刻所在的多个场景按源码顺序取第一个为当前场景；列表仍展示所有有效声明。不推断 JS/Canvas、GSAP 时序或字幕类名。
- `<audio src data-start data-duration>` 读取已有协议；缺省 start=0 与当前播放器一致。字幕只读取显式 `data-motion-role="caption"` 且有 start/duration 的静态节点，或明确标识同角色的 composition；它是可选展示提示，缺失不影响生成、播放、导出或交付。
- 新增只读 `POST /api/projects/:id/motion/structure`，请求 `{filePath, source?}`。有 source 时仅解析该份有界文本，用于 UI 当前实际预览的冻结/内联来源；无 source 时通过已有项目文件读取边界读取作品，供 CLI 使用。授权仍是项目 read，不写文件或 DB，不接受项目外路径；输入限制与异常返回采用已有 API 错误形状。
- UI 与 `od project motion inspect <file> --project <id> --json` 使用同一端点。CLI 可选 `--source-file <path|->` 以 inspect 未保存文本，与 UI 语义一致。长修改要求继续走原有 comment `--prompt-file`，不把 inspect 变成生成入口。
- 响应指纹计算的正是本次解析字节。UI 发送 previewSource 并核对响应与当前 fingerprint，忽略迟到请求；不拿 daemon 磁盘原文 hash 和经过内联/冻结的预览 hash 直接比较。流式生成、非活动预览或手工编辑时不请求。

### Web 与既有标注接续

- 新组件承担场景/可选媒体行和场景内容选择，`MotionPlaybackControls` 保留原播放栏、画面缩略图、时间输入、标尺和批注。场景与内容行放在透明 range 命中区域外，轨道只提供选择/定位，不出现拖拽裁剪外观。选中场景之后展示关键文字按钮与“标注并修改”。
- 画布与面板占位继续共享一份高度，条件行增加高度由相同计算决定；窄栏对象列表可滚动，不新增长驻侧栏挤压画布。
- 场景/文字选择由 FileViewer 的一次受保护操作处理：requestComposerRetarget → 当前来源/文档核对 → 解锁旧标注 → seek/暂停 ACK → 核对身份 → 清旧已确认放弃的 composer → 更新选中。每个 await 后都核对 source 与 transport token，处理中拒绝重复操作。
- “标注并修改”对可唯一定位的场景/文字 selector 调用已有 validateCommentSaveTarget，得到当前真实 position/style/selector；等待 lock ACK 后进入既有 composer。不可见/不存在/文档变化则提示重新选时刻，不制造位置。声音/字幕若无可见目标，走所属场景标注或仅时间定位，不给音频画框。
- 新结构目标使用严格 Motion 验证选项：运行时 querySelectorAll 必须唯一，检查目标及祖先的 display/visibility/opacity 与视口相交；URL 与 srcdoc 桥使用同一规则。普通旧评论不扩大门槛。覆盖运行时重复 selector、祖先透明/隐藏的回归，严格验证失败只保留定位并提示。
- 场景名称、区间和对象名称作为用户可见的起始批注文字；真实目标 selector 与当前 motion 时间/来源、截图继续走已有 comment DTO/API/CLI 和聊天上传。保存前再次校验真实目标；新建批注携带的旧 motion fingerprint 与当前来源不同时禁止提交，保留草稿。
- 冻结预览和非冻结 livePreviewSource 分别记录身份。结构选择请求、结构新批注草稿保存/发送共同边界，在覆盖 target.motion 前及每个异步目标验证/截图/图片转换完成后核对非冻结来源指纹、文件和文档代次。live 来源已改变，即使画面仍冻结也保稿并阻止旧提交；不等待预览解冻才失效。测试须在 boardMode 下换 liveHtml 后确认保存/发送均不调用下游。
- 不增加聊天协议、模型调用路径、版本写入语义或运行时多 Agent。当前 UI 模型保持用户选择；真实验收若发送一条要求，使用独立副本并明确这不是对照评测。

### 检查范围

daemon parser/HTTP/CLI 聚焦测试覆盖：ECOTREE 五幕/标题、音频/字幕有效与缺失、坏时间、重复 selector、单源回退、来源一致、授权和路径边界；Web 定向覆盖 ACK、来源改变、草稿确认、真实验证后的目标与原评论通道、窄布局。运行 guard/typecheck，不运行全量 Web/daemon 套件。浏览器验收原播放器与新选择/标注路径；单独合成的媒体测试样例需明确演示来源，不能冒充真实用户作品或新的 A/B 结果。

## 实现与验收记录

- UI、HTTP 和 CLI 已按同一只读结构契约接入。实际 ECOTREE 读取到五幕和五个标题，无音频/字幕；独立声音字幕演示样例读取到五幕、一个 0–12 秒的真实合成 WAV，以及一个 5–8 秒的显式字幕节点。示例文件仅通过本地正式项目 API 创建，不覆盖此前作品与 A/B 记录。
- 实际浏览器中选择第三幕，播放器暂停到 6.5 秒并同步文案列表；选标题后进入原批注编辑器，真实 h2 框与 72px 属性可见，起始批注含场景名、5–8 秒范围和对象文字。选择字幕条也实际定位到 6.5 秒，画面字幕、字幕条和已选内容一致；声音行展示真实资源名称与声明区间，没有波形装饰。
- 验收发现 Motion runtime 会在根外插入布局容器，导致原始 body 路径失效；解析器已改为锚定最近的唯一祖先 ID，真实第三幕标题为 `[id="scene-3"] > div:nth-of-type(1) > h2:nth-of-type(1)`，并补上包裹容器和重复祖先 ID 回归。
- 从该标题发送了一次真实修改：72px → 68px。源文件比较确认只替换 `#scene-3 h2` 的这一处数值，其他字节不变；界面显示已完成。界面曾显示约 31–35 秒，不用该数字代替服务端精确耗时，也不声明效率提升。未独立证实模型消费截图像素。
- 成功发送结构反馈后退出旧标注冻结，恢复后续实时作品预览；错误或未确认放弃时保留原草稿。集成测试覆盖真实 transport ACK、严格目标回复、PNG 协议转换、原发送回调、自动解锁和新来源重新读取。测试快照是明确的一像素 fixture，只证明链路与状态。
- 声音/字幕样例中还观察到部分缩略图首次视口为零，作者 fit 保持 scale(0)。已在宿主定位命令后和文档 load 时按帧重触发作者 resize/fit，不等待所有媒体下载才处理，也不使用持续 resize 观察循环。定向回归验证只接受 parent 的定位命令，零视口变为 1920px 后恢复 scale(1)。该最后修正尚未补拍浏览器像素证据，不能将修正前截图说成最终渲染证明。
- 检查使用 Node 24.15.0。contracts/daemon 构建、daemon 源码/测试 typecheck、全仓 guard/typecheck 通过；Web 严格目标校验两文件 30 项、daemon URL 定向 2 项及静态解析器 10 项通过。组件/集成定向通过；资源压力下组合复验出现超时，随后修正“请求已发出即视为 UI 已恢复”的测试等待，最终单 worker 集成复验 5/5 通过（20 秒用例上限，实际测试 1.67 秒），最终缩略图回归 4/4 通过。未运行全量 Web 或 daemon 测试。

本地入口：主示例项目 `motion-tracks-20261026`，声音/字幕演示项目 `motion-tracks-media-20261026`。预览继续使用现有隔离 namespace；最后重新打开内置浏览器的请求返回 queued，回到此对话时才显示，不将 queued 当作页面已打开。截图、完整运行参数、CLI 回读和检查日志在本地忽略的验收目录内。
