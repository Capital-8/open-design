# Motion 预览与编辑界面精简方案

日期：2026-10-28。状态：方案评审后，用户已授权“按照建议优化一版”；本地实现与验收记录见第 7 节。前六节保留评审时的判断与取舍。

## 1. 结论与评审范围

建议通过：**默认只展示播放控制和一条缩略图时间轴；修改目标、对象属性和动画参数按任务展开。** 不继续给默认播放器增加常驻轨道或工具行。

截图中的界面实际是 `MotionPlaybackControls` 预览审阅区，不是上轮新增的三栏 `MotionObjectEditor`。两者现在并存，因此只优化独立编辑器不能解决截图中的问题。此次优先精简用户首先看到的预览区，同时约束进入直接编辑后的信息层级。

评审组织：一位交互设计方向 Agent、一位产品经理方向 Agent 分别查看截图并独立只读审查；主审核对代码能力、合并分歧。这是多视角专家评审，不是外部真人专家认证或用户实验。

依据：用户本轮截图、当前工作区组件、[已有 Figma / Jitter 实操研究](./figma-jitter-editor-scope-20261028.md)、[上一版产品与技术方案](./PRD-motion-object-editor.md)。不重新假设竞品最新状态，不将启发当作有效性测量。

核心问题是信息组织：观看、时间定位、解析出的场景与文字、批注、修改、对照被摆在同一层。用户必须先理解这些区别，才能找到下一步。缩小字体、减少间距只会让阅读更困难，不能消除选择负担。

## 2. 逐项处理决定

| 截图中的信息或操作 | 处理 | 理由与保留路径 |
| --- | --- | --- |
| 缩略图上的 `index.html` | 移除默认显示 | 文件名是产物载体，不帮助定位画面；原文件导航仍可查看。内部路径和版本绑定继续保留。 |
| “画面”标签、电影图标和素材外框 | 精简成视觉导航 | 当前整片 HTML 不是可裁切视频素材；不使用可拖边、可剪切的视觉暗示。保留真实缩略图和播放头。 |
| `01 Main scene` 整行 | 单场景隐藏 | 只有一个、覆盖全片时没有导航收益。多场景才在同一缩略图条上显示分界和名称，窄片段通过提示和场景列表定位。 |
| 下方再次 `Main scene 0–5s` | 删除重复标题 | 与场景条、作品总时长重复。选定场景作为修改目标时，在输入区展示一次。 |
| 空“批注”轨及空提示 | 空时不显示 | 没有批注不需要一行占位；创建入口保持可见。有批注则在时间轴固定窄标记带显示，密集标记聚合，可打开列表。 |
| 一整行全文标签 | 默认收起 | 把画布文案抄成一串按钮，长文本难扫描，也不代表都可直接编辑。修改面板提供可见“选择元素”入口，列表用于遮挡、未出现或难以点中的对象。 |
| “标注此刻”与“标注并修改” | 合并为一个“提出修改”入口 | 不要求用户先猜时间标注和对象标注的差别。打开后显示目标，并显式区分“保存批注”和“让 AI 修改”；打开面板不调用模型。 |
| “编辑区间” | 更名“选时间段” | 代码仅选择反馈范围，没有裁切或改片长。入口保留在控制栏，打开后才显示起止设置；不能承诺范围外绝不变化。 |
| “保存对照帧” | 移入更多菜单 | 低频且需要预先准备，默认占位收益较低。命名“保存参考画面”；已有参考时显示“查看画面对照”，保留会话临时性的说明。 |
| 时间码、尾部时长、场景时长、帧数/FPS | 合并重复显示 | 默认一处当前时间/总时长；尺标用于空间定位保留。默认显示到百分之一秒，点击输入显示完整值，可切换帧定位；只改变显示，不舍弃原始精度。FPS 放精确定位或作品信息。 |
| 播放、前后逐帧 | 保留 | 本场景是精细微调，逐帧是高价值且占位小的直接操作。图标必须有“上一帧/下一帧”提示及读屏名称，不能让人误认成切换素材。FPS 未知时明确为小步跳转，不称逐帧。 |
| 重播 | 移入更多 / 播放结束态 | 与回到起点再播放重复；结束时主播放按钮可表达重新播放，不需要默认常驻第四个播放命令。 |
| 音量 | 按已知能力显示 | 确知无音源时移出常驻区；结构未解析到音轨并不证明无声音。没有可靠信号前先保留声音控制，不能为了整洁误删。 |
| 连接失败、未保存、版本冲突、正在提交 | 保留发生时的明确反馈 | 这些信息会影响下一步决策，不能一并塞入更多或仅靠短暂 toast。正常状态不保留空错误栏。 |

这些是减少默认暴露，不是删掉帧定位、标注、缩略图、对象选择或比较能力。`源版本`、对象 ID、时间范围属于必须传给系统的上下文，不必原样陈列给用户。

## 3. 建议界面与展开规则

### 默认看作品

```text
                         作品画布

00:04.92 / 00:05.00     [上一帧] [播放] [下一帧]     [选时间段] [提出修改] [⋯]
0s ───── 缩略图、播放头、必要的场景分界和批注标记 ────────────── 5s
```

上图是结构示意，不是已实现截图。真实缩略图仍保留，不能退化为一条无法识别内容的进度条。场景分界、批注标记共用时间坐标，各自有区分和可点击区域；若密集，打开列表，不堆叠新轨道。

受支持作品的“编辑动效”保留在作品工具栏，与“提出修改”明确区分。前者进入直接操作，后者打开反馈输入；不能点击同一个按钮后静默切换成模型调用。仅 Motion 任务使用这套界面。

不增加“新手 / 专业”“查看 / 审阅 / 编辑”三四个模式开关。用户通过现有的播放、提出修改、编辑动效动作进入对应状态。

### 提出修改

打开后暂停在当前画面，复用现有侧栏，不再追加底部横条。输入上方展示简短目标：

```text
修改目标  [当前画面 ▾]         时间  [4.92 秒]
[选择元素]                    [改为时间段]

描述希望修改的内容……

[保存批注]                              [让 AI 修改]
```

- 默认针对当前画面和当前时间。选择元素后显示可识别名称，如“主标题”，长文案放详情，不再整段抄成标签。
- “选择元素”在面板内可见，支持列表定位；不能只保留画布点选、右键或快捷键。列表如只有文本识别能力，应如实标识，不假装包含所有图层。
- 对象与时间范围可以并存，例如“主标题 · 1.20–2.40 秒”；两者分别可更改或清除，不能互相静默覆盖。
- 时间段只表达反馈重点。说明放在范围设置内：“此时间段将随修改要求发送给 AI”，不使用锁定区间或范围外不变的承诺。
- 查看范围设置时先编辑草稿；确认“使用时间段”才生效，取消不留下默认选区。现有组件一打开便写入场景范围，这点需要改变。
- 发送完成或明确取消后清除临时对象/范围；保存的批注保留自己的上下文。重新打开新修改默认使用当前画面，避免继承旧目标。关闭但保留草稿时，下次打开必须可见地恢复同一上下文。
- “保存批注”与“让 AI 修改”是不同提交，绝不因原来只想留言而自动运行模型。

### 直接微调

进入已实现的受控对象编辑器后，画面只保留一套底部动画时间轴，不再叠加外面的缩略图、场景、批注、全文标签。

- **外观页**：以画布和对象属性为主；时间轴可收起到播放栏，保留明显“展开动画时间轴”入口，不能连定位能力一起藏掉。
- **动画页**：展开动画片段。当前这种 10 个对象的单场景先保留整体节奏，选中高亮并滚动到可见位置；不因选择对象就自动过滤其余轨道。
- 对象多时提供明确“仅看所选”切换；用户主动过滤后持续显示过滤状态及“显示全部”，避免误以为其他动画丢失。
- 多选之后才显示错峰等组操作。外观和动画中都保留保存状态、撤销重做及失败恢复。
- 进入或退出保留已保存版本和播放位置；选择暂时不可见对象时提供明确的“定位到出现时刻”，不静默跳到另一时刻导致用户失去上下文。
- 直接编辑仅对可靠绑定的作品开放。无绑定作品仍可以提出修改，不展示不可用的伪轨道或悄悄改成 AI 执行。

### 音频、字幕与多场景

真实存在相关内容时可以出现“声音 / 字幕 / 场景”入口，按需展开已有导航，不默认扩成多轨剪辑台。必须区分“能定位并交给 AI 修改”和“可直接拖动裁切”。本轮不新增音频编辑、字幕编辑或高级关键帧。

## 4. 评审分歧与最终取舍

1. **逐帧是否默认收起？** 两位评审都认为可以渐进展示。主审决定本轮保留前后逐帧：用户目标正是精细修改，两个小按钮比空轨和重复信息更有价值。先删低价值层，不先藏核心操作。
2. **动画时间轴是否默认只显示选中对象？** 设计评审提出聚焦所选。主审采用“默认保留当前场景整体，显式切换仅看所选”：本例只有 10 个对象，自动过滤会削弱判断错峰关系的能力。
3. **时间段是否完全放进修改面板？** 保留控制栏入口，便于先圈时间再描述问题；具体起止参数只在设置时展开，与修改面板共用同一份状态。
4. **要不要自动保存前后对照？** 暂不做。当前是手动保存一张临时参考图，不是完整版本或动态对比。先移入口，不能靠改名升级能力承诺。

两位评审的共同意见是：不要把所有功能藏进更多；不要为了更干净删除定位和对象查找；不要将任意 HTML 假装成可以可靠拖动的图层。

## 5. 工程可行性与实施边界

结论：主要是前端信息组织和交互状态整理，不需要改生成模型、作品格式或渲染器。可以增量实现，但入口合并不是单纯 CSS 修改。

| 改动 | 判断 | 必须验证的风险 |
| --- | --- | --- |
| 隐藏文件名、单场景条、空批注、重复时长 | 低风险，可直接条件渲染 | `motionDockHeight` 和画布可用高度一起调整，避免留下空白或挡住画面。 |
| 场景/批注合到时间导航，全文列表按需打开 | 中等，复用现有数据和选择回调 | 多场景窄片段、密集标记、键盘和读屏可达；选择列表不能丢对象身份。 |
| 合并修改入口、目标与范围草稿 | 中等，状态收敛 | 当前时间、对象、范围、批注草稿的组合与清空；已有版本校验、请求互斥、权限及错误处理继续有效。 |
| 直接编辑器折叠、显式过滤、跨入口保留时间 | 中等，局部 UI 状态调整 | 草稿不丢失、过滤有提示、播放头不跳、所选轨道完整可见。 |
| 参考画面、精确时间入口移动 | 低至中等 | 保留截图失败/过期提示和已有精确定位，不升级为持久版本对比。 |
| 无声音时隐藏音量 | 依赖真实能力信号 | 当前播放器无条件展示，不能仅以 `structure.audio.length === 0` 判断无声。不能证明前先不改。 |

代码核对点：

- `MotionPlaybackControls.tsx` 同时渲染工具行、场景行、空批注行、`MotionSceneContents` 和帧统计，属于累计展示，并非底层必需。
- `MotionStructureTracks.tsx` 场景按钮是选择/定位，全文列表枚举当前场景文本；不是动画编辑数据。
- `MotionRangeEditor.tsx` 通过 `onChange` 设定范围；打开无范围时立即调用 `currentSceneRange()`。不执行裁切。
- `FileViewer.tsx` 的 `selectMotionStructureItem` 负责暂停/定位、验证目标和打开批注草稿；合并入口必须保留这些保护。
- `motion-timeline.ts` 当前单场景且有内容时的底部高度为 `210 + 32 + 62 = 304 CSS px`，尚未加入真实音频/字幕轨。

落地顺序建议：先精简默认区域与术语，再合并目标输入，最后整理直接编辑器的折叠和过滤。不借本次评审改渲染、模型调用策略或音视频编辑能力。

## 6. 如何判断改善

**可直接验收的结构目标：** 相同桌面宽度下，单场景、无额外媒体、无展开面板时，底部从当前 304 CSS px 收敛到约 144 CSS px，释放约 160 px（约 53%）。这是待实现的布局目标，不是截图实测或理解效率提升；无障碍缩放和窄窗口不能为凑数字压缩点击区域。

其他结构验收：默认只两层；单场景不重复出现；不存在空批注轨和全文标签带；只有一个主要反馈入口；有批注时标记仍可达；精确时间和对象列表不依赖隐藏快捷键。

**用户效果待验证：** 用 5–6 位目标用户做方向性可用性检查，新旧顺序交叉、任务等价，不能将小样本宣称为统计显著。任务覆盖：

1. 找到标题刚开始出现的时刻并逐帧定位。
2. 找到被遮挡或尚未入场的标题，针对它提出修改。
3. 针对指定时间段提出节奏修改，并复述修改对象与范围。
4. 找到已有批注并回到对应画面。

记录首次有效操作时间、无需指导完成数、误入口次数、错误对象/范围提交数、总完成时间。保留原始逐任务记录，报告中位数和失败原因，不只问“好不好看”。若出现用户找不到逐帧或对象入口，或误以为选区就是裁切，应修改方案后再验。

截图里蓝色卡片文案已有明显裁切，这是作品结果问题，不属于可删的信息。先记录为长文本编辑验收案例；本轮不推断原因、不擅自改用户文案，也不把自动缩字扩进这次界面精简。

实现内容：

- 默认仅播放栏与真实缩略图时间轴；去掉文件名、单场景重复标题、空批注行、全文标签和重复帧统计。多场景和已有批注仍有时间轴标记与列表入口。

- 正常状态不预留错误栏；错误、锁定和保存状态继续可见。直接编辑仍要求受控绑定，未扩大任意 HTML 的直接修改能力。

已验证的结果：

- 在 1280 × 720 浏览器视口，播放器 DOM 实测高 **144 CSS px**。此前同类单场景布局由代码计算为 304 px，减少 160 px / 52.6%；这是布局占用比较，不是用户效率或模型成功率实验。
- 浏览器验证精确定位到 2.5 秒；进入编辑器、选中主标题、切换动画页及仅看所选、返回预览后仍为 2.5 秒。外观页折叠和动画页展开均有截图。
- 播放器、时间范围、结构导航、对象编辑器和反馈上下文的相关定向测试已通过；`pnpm guard`、Web TypeScript 检查通过。没有运行无关全量套件。
- 浏览器验收暴露并修复零高度场景容器的反馈定位问题：当前画面优先定位声明的 composition 根节点，继续执行唯一性、可见性及版本校验；没有可靠目标时才退回显式画布选择。零高度场景、可见根节点和隐藏根节点均有回归覆盖。
- 浏览器实际完成“提出修改 → 选主标题 → 设置 1.20–2.40 秒 → 保存批注 → 从时间轴重开”，保存后恢复播放控制，重开保留语义目标名称和范围；同一时间点的两条验收批注正常聚合。修复了重校验时语义名称退化为 `div.content.text` 的问题，并去掉 Motion 选框的 DOM 路径标签。
