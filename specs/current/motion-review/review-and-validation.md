# Motion 时间点反馈：评审与本地验收

## 结论与交付范围

建议投入首版。价值在于把参考时间、目标元素／区域、当前画面和修改要求一起交给 Agent，减少用户解释对象的成本。用户反馈与一手竞品资料支持此方向；减少修改轮次、提升满意度的效果尚未量化验证。

本地实现位于 `codex/motion-review-20261025`，基于 main `9724c44142`。方案见 [产品需求](./product.md) 和 [技术方案](./technical.md)。2026-10-25 首版验收没有调用模型；2026-10-26 已补充[实际模型对照](./experiment.md)。没有创建 PR、合并或发布。

首版支持 canonical Motion HTML 的播放控制、精确时间与帧步进、暂停评论、当前画面截图、区域标注加入对话草稿、历史评论回看，以及 CLI 时间点评论。MP4 统一批注、多轨、关键帧和区间编辑留在后续。

## 真实浏览器见证

通过正式项目、会话与文件 API 创建隔离演示项目，使用本地 GSAP 样本，不伪造生成 Run。

1. 宿主时间输入定位到 2.4 秒，连续前进三帧后，播放器与作品内时钟均为 2.500 秒。
2. 点击“标注此刻”并选中标题。时钟停止，播放和定位禁用，画面没有继续移动。
3. 保存元素评论。正式评论 API 回读 `timeSeconds=2.5`、`durationSeconds=8`、`fps=30`、来源指纹、原位置及 PNG 附件。
4. 实际打开保存图片，画面非空，标题位置和作品内的 2.500 秒标记一致。
5. 在第 5 秒框选标题并加入输入框。真实上传图片带红色框与 5.000 秒画面，文字和图片出现在对话草稿；未按发送按钮。
6. 上传后仍停在 5.000 秒；退出区域标注后可从该处继续播放。
7. 从播放状态打开历史评论，预览暂停并回到 2.500 秒。
8. 缩窄预览后打开历史评论，元素标记仍对齐标题，编辑浮层正常打开。修改文字并保存后，正式 API 回读确认原时间、位置、截图附件和来源文件均未改变。

普通 HTML 预览未出现 Motion 播放器。最终截图和运行身份保存在本任务的本地预览验收材料中；运行数据隔离遵循根 AGENTS.md 的 Daemon data directory contract。
