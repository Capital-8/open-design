# Motion 编辑工作台：竞品核查与改版建议

核查日期：2026-10-26。决策题：让生成后的动效更容易定位、指出问题和修改，Open Design 应该怎样从播放器走向编辑工作台？

## 结论

建议采用“画布 + 场景时间线 + 带上下文的 AI 修改”布局。首版先改善审阅和反馈，随后补充文字、颜色、位置等直接编辑。通用多轨剪辑、关键帧和曲线编辑属于另一层工程能力，需要单独评估。

最值得优先参考的是 **Hera 的轻量场景条、Motion.so 的标注与 AI 衔接、Jitter 的选中对象上下文**。Lottie Creator 用来判断后续精细编辑的完整成本；Motion Studio 用来参考代码动画如何预览、应用与撤销。

本轮是公开资料与公开界面研究，未登录这些产品完成模型生成、手工修改、保存或导出的实测。没有竞品效果排名，也没有由竞品宣传推导的效率提升比例。

补充核查的两个对象：

- **Kario**：官网明确将输出描述为可编辑场景、图层、关键帧，并支持手工与对话修改，值得后续做真实项目实测。本轮只核对了官方说明，没有验证其工程可编辑程度，因此不优先用它决定界面细节。[官方功能页](https://www.karioai.com/ai-motion-graphics-generator)、[MCP 文档](https://www.karioai.com/docs/mcp)。
- **Motion Studio / motion.dev**：与 Motion.so 是不同产品。它在运行中的网站上发现动画、提供轨道与关键帧编辑，并将预览修改 Apply 到源码；AI 可得到选中轨道上下文。它更接近代码动画的工程参考，不是整段 Motion 视频生成的直接替代。[编辑文档](https://motion.dev/docs/studio-editing)、[Ultramotion](https://motion.dev/docs/studio-ultramotion)。本轮没有核实其速度宣传，不能把该宣传迁移成 OD 的性能预期。

纯粹输出像素视频的生成器不作为本轮核心对象，因为本次决定依赖“生成后继续精确修改”的编辑面，而非首次生成画面的能力。

## 当前界面的问题

基于用户截图和本地 `MotionPlaybackControls.tsx` / CSS 的核对：

1. 时间线是原生 range 滑杆，只能表达进度，不能表达场景、修改点与反馈分布。
2. 秒数输入框、单位、帧信息和按钮并列常驻，视觉上更像调试工具，主操作没有明显层次。
3. “标注此刻”处于工具条边缘，用户难以从界面直接理解它与播放位置、画面对象、聊天修改的关系。
4. 画面与控制区的布局优先满足播放，缺少工作台的空间分区；仅改变颜色和圆角不能补上这些信息关系。

这些是界面与实现观察，以及设计判断；不等于已经证实它们导致首次修改失败或增加修改轮次。

## 建议的工作台

```text
项目 / 当前动效                                      预览 / 导出
┌──────────┬─────────────────────────┬──────────────────┐
│ 场景     │ 画布工具、当前场景、适合窗口 │ 上下文 / 修改清单   │
│ 01 开场  │                         │ 00:06.800         │
│ 02 测量  │       动效画布            │ 当前场景 / 画面落点 │
│ 03 细节  │       点选 / 圈选         │ 已有批注与修改意见  │
│ …        │                         │ 输入修改要求       │
├──────────┴─────────────────────────┤ 带上下文交给 AI    │
│ 时间码       上一帧  播放  下一帧       标注此刻            │
│ 标尺     0s     2s     4s     6s     8s    10s   12s   │
│ 画面     [开场][ 测量 ][ 产品细节 ][适配][CTA]          │
│ 批注                    ①          ②                │
└───────────────────────────────────┴──────────────────┘
```

这是一张工作区职责草图；接入产品时复用现有聊天区，不新增一个独立 AI 对话系统。侧边的上下文 / 属性按需展开，窗口较窄时收起场景目录，优先保留画布、时间线与修改入口。

### 首版：先把定位与反馈做好

- **中央画布**：放在中性灰工作区内，保持作品原始比例；选中或标注状态有清晰反馈。工作台的视觉样式与作品本身分开。
- **紧凑播放栏**：时间码在左，播放与逐帧在中，“标注此刻”在右。点击时间码才进入编辑；输入期间暂停，避免播放时钟覆盖输入。已知 FPS 才显示帧与逐帧控制，未知时使用秒。
- **底部时间线**：用刻度、细播放头和片段条表达时间；首版以定位为主。存在明确且可靠的场景起止信息时展示场景块，缺少时只展示一条完整动效，避免猜出的分镜误导用户。
- **批注轨**：将来源指纹与当前内容一致的时间批注显示在对应位置，点击可跳转；密集批注聚合。来源不一致时展示原截图并提示“来自旧内容”，不能将旧时间与对象直接套用到当前动效。首版不承诺恢复旧工程；真实历史版本回放需另行建立版本标识与内容恢复能力。
- **上下文接续**：时间码、当前画面、区域 / 元素引用形成一张修改卡片进入现有聊天。提交前可检查目标；修改后回到对应时刻验证。当前版已有暂停、截图、时间与目标信息传递能力，视觉改版应复用该链路。

首版的收益假设是“更快找到问题、更少手写定位信息、更容易回看修改”，不是已证实的模型能力提升。

### 下一层：直接改明确属性

参考 Hera、Jitter：确定的文字、颜色、位置等改动直接操作，涉及节奏、风格、连续动作的改动交给 AI。落地前需要稳定的元素身份、可写属性、持久化与撤销能力；不能只改预览 DOM，刷新或下一次 AI 修改就丢失。

### 多轨与关键帧：在编辑对象明确后推进

当前 GSAP 主时间线支持时钟和定位，但不等于具备统一的“图层—片段—属性—关键帧”编辑文档。拖拽缩短场景可能同时影响后续节奏、音频、结束状态与导出。需要先明确这些操作的写入语义、撤销、源码同步和导出一致性，再显示对应手柄与曲线编辑器。Motion Studio 可作为“预览草稿 → 应用到源码 → 撤销”的参考。

## 改版怎样验收

| 要验证的优化 | 测量方法 | 当前状态 |
| --- | --- | --- |
| 更快找到场景 / 问题帧 | 同一动效、同一目标，记录从任务开始到正确暂停位置的耗时与误跳次数 | 待做新界面的用户对照 |
| 减少准备修改意见的操作 | 记录暂停、定位、标注、输入到提交的总耗时、操作数和手写定位字数 | 待测；此前模型实验未覆盖这段 |
| 反馈上下文完整 | 检查来源指纹、实际确认时间、目标与截图是否一致，以及模型输入是否收到 | 可复用已有链路检查，改版后补验受影响部分；来源指纹不等于可恢复版本 |
| 能找到并回看反馈 | 找到指定批注；来源一致时跳转对应时刻，不一致时查看原截图与旧来源提示 | 待做关键用户路径验证；不包含恢复旧工程 |
| 不挤压作品与编辑入口 | 检查常用桌面宽度与侧边栏展开状态，无控件遮挡，文字可读，键盘可用 | 草图尚未完成浏览器验收 |

首次修改成功率、轮次和模型耗时继续保留，但不能替代前面的交互成本。此前 3 个任务 / 6 次模型修改中，两组都首轮通过；这一结果不能证明新工作台有效，也不能拿来给本次草图背书。详见 [实验记录](./experiment.md)。
