# Open Design Motion 编辑器：功能边界与交互深度

日期：2026-10-28。状态：竞品实操后的产品建议稿，供需求与技术评审；本轮不实现产品代码。

## 1. 建议决定

将 Open Design 的 Motion 工作台升级为**以元素和动画片段为核心的精细编辑器**。用户生成初稿后，常见的改字、改样式、移动元素、调整入场时间和速度，应能直接操作并立即预览；复杂重排、风格探索和新增场景继续由 AI 完成。

默认交互借鉴 Jitter 的“元素 + 动画片段 + 少量参数”，高级控制借鉴 Figma Motion 的“属性 + 关键帧”。第一版先把直接编辑、保存、撤销、重新生成后的继续编辑做完整，再扩展关键帧深度。

这会改变上一版的范围：上一版解决了定位、标注和修改前后检查，适合作为评审工作台；若定位为精细编辑器，就应加入可信的直接参数编辑。不能仅靠时间轴外观升级来完成这一步。

## 2. 研究对象、方法与证据边界

决策题：对主要通过提示词生成品牌宣传、产品介绍、文字动画和社媒短片的用户，Open Design 应提供哪些后续编辑能力，哪些细节应由用户直接控制？

本轮为专家体验与功能范围研究，不是效率 A/B 或市场需求规模验证。原定观察任务为内容微调、入场节奏、多元素协调；实际根据可用样例操作，未强行统一成同一份素材。

| 对象 | 本轮确认的身份 | 体验环境 |
| --- | --- | --- |
| Figma Motion | Figma 内原生 Motion 模式，界面标注 Beta；不是 Figmotion 或第三方 Motion 插件 | macOS / Edge，用户已有登录，复制 Config 2026 Playground 后操作；套餐未核实 |
| Jitter | 独立 Motion 设计编辑器，以 Design / Animate 两种模式组织编辑 | macOS / Edge，用户已有登录，复制 Getting Started 后操作；套餐未核实 |

## 3. 实际操作与收获

### 3.1 Figma Motion

在副本的 Motion 页选择 Goal Dark 示例，时间轴展开 Chrome illustration 的 Position 和 Scale，初始显示 2 个属性轨、9 个关键帧。

| 操作 | 实际结果 | 对 Open Design 的启发 |
| --- | --- | --- |
| 双击 Scale 的 1.000 秒关键帧 | 播放头定位至 1000ms，右侧显示该对象在该时刻的缩放 | 画布、选中对象、播放头、属性面板必须共享选择状态 |
| 将缩放 100% 改为 80% | 锁定比例下 X/Y 均变为 80%，画面变化；撤销后回到 100% | 明确数值应走即时、确定性修改，并可一步撤销 |
| 拖动缩放结束关键帧 | 从 1.000 秒移至 1.398 秒；刷新后仍为 1.398 秒 | 拖动适合找节奏，精确输入适合最终校准；需要两种入口 |
| 点击两帧之间的连线 | 出现 Easing 设置，原值为 Custom spring / Bounce 约 0.67 | 缓动属于动画区间，不应混在静态样式里 |
| 选择 Gentle | 显示 Gentle，Bounce 变为 0.25 | 常用预设应直接可选，自定义曲线和弹簧参数按需展开 |

证据：`figma-before.png`、`figma-scale80.png`、`figma-timing-easing.png`、`figma-reopened.png`。刷新验证覆盖关键帧时间；刷新后的 Gentle 参数没有再次完成面板回读，不将其单独记为持久化通过。未执行 Figma 文案替换、多元素错峰、AI 生成、视频导出。

体验判断：精确定位和数值修改的控制感强，但层级、属性轨、关键帧、缓动之间存在学习成本。不能将它所有属性和工具直接搬到 Open Design 首屏。

官方依据：[时间轴](https://help.figma.com/hc/en-us/articles/41405906446999-Use-the-Figma-Motion-timeline)、[关键帧](https://help.figma.com/hc/en-us/articles/41307938657559-Add-select-and-delete-keyframes)、[缓动](https://help.figma.com/hc/en-us/articles/41414048690839-Adjust-an-animation-s-easing)。官方支持时间输入、轨道移动、关键帧和缓动；自动关键帧会记录属性变化，也会带来误操作风险。

### 3.2 Jitter

在副本选择 New book promo post 场景。画面包含标题、书封图片和两段文字；时间轴显示各对象的 Mask in / Grow in 动画片段。

| 操作 | 实际结果 | 对 Open Design 的启发 |
| --- | --- | --- |
| 选择 Body text 1 的 Mask in | 画布文字、左侧图层、底部片段联动高亮；右侧呈现方向、距离、时长、缓动及文字分段参数 | 时间轴应表达“哪个对象正在做什么”，不只列出素材类型 |
| 时长 900ms 改为 600ms | 对应片段变短；在 3 秒处可查看完整画面，其他对象仍在 | “快一点”优先用时长控制，不必先学关键帧 |
| 切 Design，双击文字 | 直接替换为两行 “Make motion / feel right.”，保留该文字的入场动画 | 改静态内容和改动画分开，但保持同一个对象 |
| 撤销、重做文案 | 撤销恢复原句，重做恢复新句 | 日常微调不应要求重新生成整段作品 |
| 多选两段文字动画，右键 Stagger，输入 0.2 | 出现错峰输入，第二段片段位置发生变化；重开后保留对应排列 | 一组对象的顺序与间隔是高价值能力；不是只能逐个拖动 |
| 刷新重开，定位 3 秒 | 新文案、600ms 时长都保留；播放按钮切换为暂停，可播放修改后的动画 | 保存重开和动画仍可播放，是直接编辑的基本完成条件 |

证据：`jitter-before.png`、`jitter-duration600.png`、`jitter-text-edit.png`、`jitter-text-undo.png`、`jitter-stagger.png`、`jitter-reopened.png`。错峰验证基于 UI 输入和片段位移，没有导出逐帧测量；不声称端到端达到 1ms 精度。未执行 Jitter AI、导出、协作权限或批量变体。

体验判断：以“入场 / 退场 + 方向 + 时长 + 缓动”组织控制，比属性关键帧更容易表达常见修改。Design 显示静态状态、Animate 显示当前时间状态，有助于防止把暂时不可见的文字误认为丢失。但首次进入复杂教程文件仍需要定位场景，部分多选命令藏在右键中，不适合原样复制给新手。

官方依据：[Design / Animate](https://help.jitter.video/en/articles/16414495-design-and-animate-modes)、[动画操作与关键帧](https://help.jitter.video/en/articles/16415500-understand-operations-vs-keyframes)、[时间轴](https://help.jitter.video/en/articles/14111802-work-with-the-timeline)。Jitter 区分持续存在的设计图层与有起止时间的动画操作，提供动画分组和错峰。

### 3.3 AI 的位置

Jitter 官方将 AI 定位为生成、重混与变体创建，并声称结果可继续手动编辑；Figma 官方也将 Agent 与原生画布、Motion 编辑结合。本轮未实际调用两家的模型，因此只采用“AI 与手动编辑共享可编辑产物”这一产品方向，不推导生成质量或成功率优势。

来源：[Jitter Superagents](https://jitter.video/changelog/2026-07-09-ai-agents/)、[Figma Motion 发布介绍](https://www.figma.com/blog/introducing-figma-motion/)。

## 4. Open Design 应该放哪些功能

首个完整版本应做到：用户无需重新发一条提示词，就能完成支持范围内的外观修改与基础节奏调整；遇到超出能力的对象，可以带着准确上下文交给 AI；二者的结果都能检查、保存和撤销。

| 能力 | 首个完整版本的深度 | 后续再做 / 边界 |
| --- | --- | --- |
| 播放和定位 | 播放暂停、逐帧、秒/帧输入、拖动定位、时间轴缩放、选区循环、适配画布 | 帧步长以作品 FPS 为依据；不能只用时间码声称导出帧精确 |
| 对象选择 | 点选画布 ↔ 图层 ↔ 动画片段联动；展示人类可读名称；重叠对象可从图层选；锁定对象避免误选 | 仅能可靠识别的对象开放直接编辑；Canvas/图片里的文字不假装是文本图层 |
| 静态内容和样式 | 文本、字体、字号、颜色、对齐；位置、大小、旋转、不透明度；图片/Logo 替换并保持容器 | 先支持文本、图片、基础形状及已验证容器；复杂 SVG、滤镜、路径形变不泛化支持 |
| 基础动画 | 选动画片段后修改开始时间、时长；入场/退场的淡入、位移、缩放及组合；方向、位移距离、常用缓动预设 | 拖动整体改变开始时间，拖边改变时长；缺可靠绑定时显示“用 AI 调整”，不能拖完再偷偷等模型 |
| 多元素节奏 | 多选整体平移，保持相对间隔；支持显式顺序 + 错峰间隔；可把一组修改作为一次撤销 | 首版限制同一场景、兼容的动画；跨场景复杂联动另行处理 |
| 文字动效 | 整体文字入场优先；可选按行 / 按词及间隔，前提是引擎稳定支持拆分和布局 | 逐字、路径文字、复杂形变后续做；中文按词分段不能靠空格假实现 |
| 场景组织 | 场景导航、名称、区间与当前场景对象；片段不得静默越过场景边界 | 场景复制、重排、整体伸缩放第二阶段，需要音视频和依赖一起处理 |
| 音频 | 仅有真实音源时显示；可定位、试听、静音；基础音量、起点、裁切及淡入淡出作为第二阶段 | 不自动生成假波形或空轨；复杂混音、降噪、自动对拍暂不纳入 |
| 字幕 | 仅有真实字幕 cue 时显示文字与区间；可定位并交给 AI 修改 | cue 内容、时码和统一样式直接编辑放第二阶段；普通标题仍归文本对象 |
| AI 定向修改 | 选对象 / 选区后输入要求；自动带目标、参考时间、版本、截图；展示修改摘要；可按整次修改撤销 | “更高级、更有节奏、新增一幕”由 AI 做；范围是目标约束，未经验证不承诺区间外绝不变 |
| 检查与恢复 | 自动保存状态、撤销重做、修改前后同时间预览；节奏变更要循环播放前后片段 | 固定截图适合视觉检查，不能验收缓动质量；多文件修改需完整事务恢复后才能称一键撤销 |
| 导出 | 延用现有导出链路，导出用户正在编辑的同一版本；显示格式、尺寸、FPS、完成与失败 | MP4 优先；GIF、透明视频、Lottie 按实际需求与格式能力另立范围，不一次承诺全格式 |

**高级关键帧放第二阶段**：只先开放位置、缩放、旋转、不透明度；支持新增、移动、删除关键帧及区间缓动。默认关闭自动关键帧。选中动画时才展开属性子轨，曲线编辑放高级入口。不首发速度图、多维曲线编辑、表达式、自由矢量绘制、3D、追踪、抠像、专业调色和完整剪辑台。

优先级依据是本轮操作观察和现有产品目标，不是已证明的用户需求占比；后续应用真实编辑请求分布校准。

## 5. 时间轴到底画什么

建议采用三级结构，但默认只展开两级：

1. **作品 / 场景**：全片的场景概览，用于导航。一个场景内部可以有多个对象。
2. **对象 / 动画片段**：标题、产品图、Logo 等对象，片段标明“淡入 / 移入 / 缩放 / 退场”，表示这个动画发生在哪一段时间。
3. **属性关键帧**：只有高级编辑时展开，呈现某属性在不同时刻的值。

对象存在区间和动画发生区间必须区分：标题 0–5 秒可见，其中 0–0.6 秒淡入；不能把 0–0.6 秒误画成整个标题素材寿命。素材视频才画帧缩略图；完整 HTML 合成称“主画面”或“场景”，不要误称一条可剪切的视频素材。

默认展示当前场景和选中对象的动画，提供“显示全部”；场景概览和缩略图合并为紧凑导航，不将缩略图、场景、文字列表、标注、比较功能堆成五六层常驻区域。音频和字幕按实际内容出现。

## 6. 交互与布局

进入 Motion 作品默认可播放；点击“编辑动效”进入专注工作区。播放器继续只服务 Motion 任务，普通网页、PPT 和交互原型不出现这套编辑器。Motion 项目的 MP4 成品也无法凭空恢复图层，展示普通视频预览并提供返回可编辑源的入口。

建议桌面布局：左侧“场景 / 对象”，中央画布，右侧“外观 / 动画”，底部时间轴。AI 以右侧可展开面板接入原会话；切换 AI 时保留所选对象，不再常驻一整列聊天和一整列图层挤压画布。

- 底部控制栏只保留常用播放与定位，范围循环、缩放可达；标注在画布或对象上下文里触发。
- 时间轴默认约 180–240px，可拖动高度和折叠；小屏缩至紧凑态，优先保住画布。具体数值需在 1280×720、1440×900 验证。
- 右侧的“外观”修改该元素的基础状态；“动画”修改某个已选动画片段。选区标题明确显示“产品标题 · 入场 · 1.2–1.8秒”。
- 进入外观编辑时如需展示静态布局，明确提示“外观预览”，保留原播放头；退出恢复原时间。不得让用户以为暂停帧发生异常。
- 选中动画显示开始、时长和缓动；高级参数折叠。拖动期间实时预览，松手形成一次可撤销修改；数值输入可精确校准。Esc 取消当前拖动。
- 快捷键限常用 Space、左右逐帧、Shift 多选、Cmd/Ctrl Z；输入文字时不抢快捷键。错峰提供可见按钮，不仅藏在右键。
- 继续使用 Open Design 的字体、灰阶和蓝色主色。选中、播放头、悬停、禁用各自含义稳定。

## 7. 关键用户路径

**改标题：** 选中标题 → 外观中改文案 / 字号 → 画布即时更新 → 自动保存 → 原动画继续播放；撤销一次回到修改前。

**让 Logo 晚出现且更柔和：** 选 Logo 的入场片段 → 开始时间加 0.3s → 缓动选“柔和” → 循环播放该片段 → 保存。不得以截图对照代替动态检查。

**三个卖点依次进入：** 按顺序多选三个对象的入场动画 → 错峰 0.12s → 显示顺序编号 → 播放预览 → 一步撤销整组修改。超过场景结束时阻止提交，并给出缩短间隔或延长场景的明确选择。

**需要重新编排：** 选场景 → 输入“产品先出现，标题再跟进，保留文案和品牌色” → AI 完成候选版本 → 显示改动对象、时间范围与摘要 → 播放检查并接受 / 撤销。AI 运行期间不允许同一对象的手动改动悄悄被覆盖。

## 8. 工程可行性与真实缺口

### 当前代码证据

核查工作区：`codex/motion-review-20261025`，HEAD `3fbd6358f038fe8715fe93298fd51b3911334597` 加既有未提交变更；这些不是线上已发布能力。

- `apps/web/src/components/MotionStructureTracks.tsx`：场景、音频、字幕是选择与定位按钮；文字列表引导进入修改，没有动画片段写回。
- `packages/contracts/src/api/motionStructure.ts`：结构包含 scene/text/audio/caption、selector、start/duration 和源指纹，没有属性动画、缓动、可编辑字段或写入契约。
- `apps/daemon/src/services/motion-structure.ts`：解析 HTML 的静态声明，不执行作者脚本，也不读取外部 composition；不能由此还原任意 GSAP/Canvas 动画的编辑语义。
- `apps/web/src/components/FileViewer.tsx`：已有手动 patch、版本保存、源变化校验；可复用保存流程，但通用 DOM 改写不等于 Motion 的持久参数写回。
- 现有 PRD 的任务门槛、逐帧、范围、批注和同帧对照可沿用。当前对照仅页面会话保留，不是完整工程版本对比。

### 推荐路线：逐步建立受控编辑能力

工程上可实现，但直接编辑必须有可靠的对象与动画数据；单独改前端控件不够。

1. **先支持一类明确的生成产物。** 为受支持的文本、图片、形状和基础动画提供对象 ID、基础属性、动画 ID、起点、时长、预设和缓动数据。渲染与导出从同一份数据构建。数据属于作品本身，不另建一份与源文件漂移的 UI 状态。
2. **界面只读取已验证的编辑能力。** 允许哪些字段、如何写回，由明确适配器决定。没有唯一字段绑定、脚本会重新覆盖的属性、复杂 Canvas 内容，仍走定向 AI。不能靠一个 `data-od-id` 或 DOM 路径就宣称可直接编辑。
3. **即时预览与持久提交分开。** 拖动可以暂态预览；松手后通过同一个服务端编辑命令校验版本、字段、边界和原值，成功后保存新版本。失败恢复预览，不伪装已保存。
4. **手动和 AI 编辑保持一个版本序列。** AI 使用同一对象身份及最新源版本；完成后重新识别可编辑能力，失去绑定的对象降级并提示。文件变更冲突不静默覆盖。多文件变更要包含资源快照与恢复清单。
5. **UI / CLI 共用接口。** 新的对象读取、动画参数修改、撤销命令需在 contracts / daemon / web / od CLI 同期闭环，支持机器读取。浏览器播放和纯视觉布局本身无需虚构 CLI 等价交互。

这是一套局部编辑的数据约定，不是要求所有旧 Motion 先转成统一格式，也不是重建通用生成计划层。旧作品仍可播放、标注和 AI 修改；新作品逐步扩大直接编辑覆盖率。若为了编辑而强制重写旧作品，应是显式用户操作，保留原版并检查视觉与时间一致性。

| 工作包 | 工程判断 | 开始实现前必须证明 |
| --- | --- | --- |
| 工作区布局、选择联动、范围循环 | 可在现有基础上增量实现，风险较低 | URL / srcdoc 两路同源状态、选区不污染草稿、非 Motion 不回归 |
| 文案和样式即时编辑 | 对受控对象可做，风险中等 | 保存重开不被初始化脚本覆盖；长文案、中文换行、字体变化正常 |
| 动画片段拖动、时长、缓动 | 需要新增动画数据与写回适配，风险较高 | 同属性多个动画、嵌套时间轴和相对时间语义明确；编辑后预览与导出一致 |
| 错峰、组操作 | 可做，依赖动画片段能力 | 边界和依赖检查、整组事务撤销，不能部分成功 |
| 场景重排与整体缩放 | 后续做，影响范围大 | 音频、字幕、转场、跨场景依赖一起正确更新 |
| 任意 HTML 全量反解为专业编辑工程 | 不承诺通用可靠实现 | 不将静态解析命中率误当作安全写回覆盖率 |

不在缺少适配原型与样本覆盖证据时承诺研发周数。建议先完成“一个受控作品，改字 + 移动入场 + 调时长 + 缓动 + 保存重开 + 撤销 + 导出一致”的最小纵向验证，再估算扩展工作量。

## 9. 发布深度与验收门槛

### 第一阶段：可以称为精细编辑器的最低完整闭环

交付第 4 节的播放定位、选择、基础外观、基础动画、同场景组操作、AI 上下文和恢复。优先支持受控 DOM / SVG 容器中的标准对象与确定性时间轴；对不支持的对象明确使用 AI。

首版基础预设控制在淡入 / 淡出、四方向移入 / 移出、缩放入场和退场，以及 4–6 个缓动预设。组合动效应保留可解释参数，不一开始建设庞大特效商城。复杂文字拆分若验证不足，可后移，不能阻塞上述闭环。

验收必须包含：

- 参数改变立即可见，保存失败可恢复；改字不意外创建关键帧。
- 同一个对象从画布、图层、时间轴进入，目标一致；旧版本引用被拒绝。
- 拖动、数值输入、撤销、重做、刷新重开得到相同结果；一段拖动只产生一次历史操作。
- 起点、时长、错峰越界有明确处理；不静默裁掉动画。
- 每类支持产物抽查起点、中间、终点的预览与导出帧；帧步进准确性按声明 FPS 验证。
- AI 编辑后手动改动无意丢失必须可检测、可恢复；对象身份变化时不允许旧控件误写其他对象。
- 普通网页 / PPT / interactive HTML 不出现 Motion 编辑器；没有音轨不造音轨。

### 第二阶段：高级控制

增加有限属性关键帧、自定义曲线、场景复制重排、真实音频和字幕编辑、动画样式复用。优先级由首版失败任务与用户请求决定。组件库、批量多比例变体、Figma 导入和 Lottie 导出应单独立项，不混入本轮最低闭环。

## 10. 量化方式与目前不能声称的结果

本轮只确认真实操作可达与局部修改结果。100%→80%、1.000→1.398 秒、900→600ms 都是编辑参数，不是效率提升数据。两产品素材不同，未计可比任务时间，未调用相同模型，不能给出首次成功率、速度领先或 Open Design 收益百分比。

后续分开验证两件事：

1. **工程可靠性**：按支持格式建立固定案例，覆盖文案、外观、时间、缓动、组操作、版本冲突。已声明支持的用例必须全部通过保存重开和撤销；不支持的案例正确降级。单独报告直接编辑覆盖率，不能把无法编辑的作品排除后宣称全量成功率。
2. **用户效率**：从真实需求取改字、改位置、晚出现、慢一点、错峰等任务，交叉安排旧流程与新流程，记录首次达标率、总修改轮次、到可接受结果的总耗时及误改。至少包括没有动画工具经验的用户。先用小样本暴露交互问题，再用足够样本验证收益；目标阈值在正式实验前确定。

建议额外记录：用户是否能分清外观与动画、找到目标的时间、从手动切回 AI 的比例、AI 修改后直接编辑能力保留率。它们能帮助判断下一步应补编辑功能，还是补对象绑定和状态可靠性。

## 11. 本轮结论

值得立项的新增核心是**可信的直接参数编辑与基础动画片段编辑**。现有播放、标注、范围和对照能力继续作为基础；新增对象—时间轴—属性联动，让用户常见微调无需等待生成。Jitter 适合作为默认交互参考，Figma Motion 适合作为高级控制参考。具体实现范围以受控对象和动画数据为前提，不能把任意生成 HTML 包装成已经可编辑的工程。
