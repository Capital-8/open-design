# Motion 精细编辑工作台首版

日期：2026-10-28。实现基线：`3fbd6358f0`。阶段：需求/技术评审后本地实现，不含 PR 或发布。

## 1. 摘要

让用户生成动效后，可以准确指出“哪个元素、哪段时间、希望怎么改”，并在同一时刻检查前后画面。首版沿用既有生成和批注链路，建立完整的定位—选择—反馈—验收流程。

## 2. 参与与评审

用户：Mason，产品目标与本地体验验收。主代理：需求、交互与集成；独立子 Agent：需求和技术评审及分工实现。内部 Agent 准出不等同于用户最终验收。

## 3. 背景

现有时间轴已有播放、逐帧、缩略图、真实场景、关键文字和可选音频字幕。主要缺口是操作入口分散、修改范围不明确、缺少便捷的前后画面对照。OpenChatCut 的对象引用、可检查的修改和共享编辑状态提供参考；详细证据见本地调研报告 `.tmp/openchatcut-research/report.md` 与评审 `review.md`。

## 4. 目标与度量

让首次使用者能从可见场景进入定向修改，并检查准确的时间/对象上下文。首版验收指标：指定场景和标题可定位；范围保存、重开与 CLI 一致；过期引用不可误发；前后对照时刻一致；普通任务不出现 Motion 工作台。交互目标是从场景选择到开始输入要求不超过三次主动点击（不计拖动/文字输入），通过实测记录而非宣称已达成。

首次修改成功率、轮次和耗时提升仍需独立 A/B，本轮不以 UI 完成代替效果结论。

## 5. 用户与任务

主要任务：改某幕标题、调整某段入场节奏、针对某帧的视觉位置提出修改。用户需要编辑控制感，但不要求掌握专业剪辑术语。首版适合已有时间轴 HTML 的 Motion 项目；普通网页、PPT、滚动交互及 MP4 不强行套用这套工作台。

## 6. 用户价值

用场景与文字名称代替难懂的元素路径；选区和参考帧清楚区分；提交前能检查上下文；修改后能按原参考时刻检查。保留现有批注保存和聊天发送，不再增加一个独立模型入口。

## 7. 方案

### 7.1 布局和交互

沿用产品字体、浅/深色 token 和蓝色 accent。预览保持主体；底部为紧凑编辑工作台：播放栏 → 时间标尺/真实缩略图 → 场景和已有媒体轨 → 选择上下文与精细操作。视觉上使用清晰分组、统一高度、稳定选中态；不堆无效轨道或装饰性波形。

- 播放栏：时间码可输入、逐帧、播放/暂停、静音、标注此帧。
- 场景行：点击场景暂停定位，文字列表与该场景同步。
- 选择条：展示所选场景/文字和参考时刻；“标注并修改”为主操作。批注编辑器显示可见上下文，不只把定位信息藏在模型提示中。
- 范围：提供“选择时间范围”开关，初始采用当前场景区间（无场景时当前时刻附近的有界区间）；双端点可拖动并提供秒数输入。开始/结束必须在作品内且开始小于结束，可清除。范围是反馈上下文，不声称锁定其他时段不变。编辑草稿形成后范围不可静默更换。
- 对照：用户在修改前点击“保存对照帧”，保存真实暂停帧与时间/来源；修改后点击“对比此帧”，定位相同时刻再截图，并以“修改前 / 当前画面”显示。仅保留当前文件、当前工作会话的一组对照；刷新后不保留，文案明确。更换文件清除，源文件更新保留旧对照。支持主动重新保存对照帧。
- 新时长短于参考时刻、截图失败、源在截图过程中改变均提示原因；禁止用其他时刻冒充对照。当前画面与旧来源相同时仍可查看，但不能声称发生修改。
- 范围首次开启取当前场景，此后切场景或定位均不自动改范围；提供“使用当前场景范围”。创建批注时复制范围快照，编辑期间禁用范围更改；退出草稿走现有防丢保护。源变化清除未提交选择，但不删除草稿文字。
- 对照保存是可选操作，不阻塞发送修改。批注/绘制/保存/发送或其他 Motion 操作进行中禁用新截图，提示先完成当前标注；已有对照可只读查看。对照截图后保持暂停。每次截图持有独立操作代次，每个 await 后核对文件、非冻结来源和 transport 代次，结束仅释放自身取得的锁；取消或切文件后旧结果不得回写。
- 范围编辑与对照区按需展开，窄栏不长期占据画布高度；对照已保存时用简短时间标签反馈。
- 固定帧对照是本期验收工具，不伪装完整版本回滚；历史文件恢复沿用现有入口和单 HTML 范围。

### 7.2 任务与运行时边界

仅 `kind=video && intent=motion-design` 的业务任务 + 声明为 Motion 视频且具有有效 composition 的 HTML 展示工作台。传递明确业务资格，不使用埋点类型代替。运行时握手后才开放操作。资格控制 dock、占位、结构读取、缩略图、transport 和托管播放注入；srcdoc 与 URL 两路一致。

Motion 项目内 MP4 用普通播放器；interactive HTML 保留交互；旧 HyperFrames/导入项目不能仅靠引擎名或误带 meta 自动启用。任务判定不修改通用产物识别/导出规则。

### 7.3 数据与技术边界

- 在已有 `PreviewCommentMotionAnchor` 增加可选 `range: {startSeconds, endSeconds}`；旧字段 `timeSeconds` 仍是截图参考时刻、`durationSeconds` 仍是总时长。校验有界、有限、start < end，旧数据兼容。
- range 经原评论 API 保存/读取、发送聊天与 CLI 输入保持一致；不建立第二份评论状态。
- UI 对象标签复用原目标与来源校验，批注草稿保留原防丢保护。无可见目标仍可标注帧；无法验证元素时给出真实原因。
- 对照复用已有暂停/seek ACK/真实截图，单独保存在 FileViewer 的当前文件会话状态。切源只保留 baseline 图像，不复用其 selector 提交修改；当前截图前后核对文档代次及来源。对照面板为现有截图的呈现，不新增服务端工程类型。
- 直接参数编辑、关键帧、场景拖拽、完整多文件恢复不纳入本期：上轮评审指出绑定与资源快照尚缺，本期不增加不可靠的控件。

## 本地验收记录（2026-10-28）

实现位于 `codex/motion-review-20261025`，基线 `3fbd6358f038fe8715fe93298fd51b3911334597` 加本地未提交变更。需求、技术评审中的条件均已落地；这是内部实现准出，最终体验由用户确认。

- 实际浏览器：第三幕→标题→标注并修改，3 次点击进入输入；范围另行设置，不计入这 3 次。5–8 秒范围保存、重开以及 `od comment list --json` 回读一致，参考帧为 6.500 秒。
- 两次真实模型调用：`deepseek-v4.1-flash`，`amr` runtime。第一条 72px→60px，30.650 秒；第二条 60px→68px，16.511 秒。各一轮执行完成，源码差异均只有目标字号。第二次复用会话和缓存，不可当作两组 A/B 或速度提升。
- 第二次实际发起修改后，播放器自动退出标注、恢复新结果；原 6.500 秒参考帧跨源更新保留，“对比此帧”捕获新结果的 6.500 秒画面。最终样式验收另用同两份真实产物重放一次文件更新，未把重放算作模型调用。
- 最终核心集成测试：4 个文件、29 项通过，覆盖范围上下文、冻结/过期拒绝、成功/失败发送、同秒对照、切源竞态和锁归属。契约、CLI/daemon、业务资格双注入路径及控件检查分别已通过定向测试；`pnpm guard`、全仓 `pnpm typecheck` 及最终 web TypeScript 检查通过。
- 范围错误输入、草稿保持、业务资格负例、音频字幕条件显示主要由定向测试覆盖；本轮实际浏览器主要验收五幕无音频字幕样例与约 630px 窄预览。没有将未执行的音视频导出/全部任务类型浏览器遍历记为通过。
- 真实验收发现并修复：已保存评论发送后仍锁住旧预览；区间清除时 blur 回写旧值；对照源变化后的锁清理竞态；对照捕获时误显示标注提示。开发热更新期间曾出现临时 CSS 缺失，刷新最终版本后布局恢复；有一次截图失败提示，后续稳定版本重复捕获成功，保留该观察而非宣称零失败。
