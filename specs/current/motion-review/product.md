# Motion 时间点标注与定向修改

## 背景与判断

用户生成动效后，常需要修改某一时刻出现的标题、布局或转场。只靠文字描述，用户必须解释时间、对象与位置，Agent 也容易找错目标。本次补齐“看到哪里，就指出哪里”的反馈入口。

**建议优先做精确定位与反馈闭环。** 用户已反馈需要此能力；直接竞品 Motion.so 官方也展示视频绘画反馈、预览内编辑和时间线编辑。证据支持投入首版，尚不能证明能减少多少修改轮次。竞品资料为 2026-10-25 官方页面核查，未经登录实测。

本地首版目标：用户能在可编辑 Motion 动效上定位、暂停、标注，并将同一时刻的截图与修改要求加入现有对话。以行为验收判断本次完成；上线后建议观察“使用时间点反馈的修改任务占比”和“首次反馈后无须重新解释对象的比例”。目前没有同口径基线，目标值与观察周期待真实试用后确定。

## 需求概览

| 编号 | 本期需求 | 改动范围 |
| --- | --- | --- |
| R1 | Motion 预览展示播放、暂停、时间轴和时间输入 | Web、桌面预览 |
| R2 | 已知帧率按帧前后移动；未知帧率按时间微调 | Web、桌面预览 |
| R3 | 标注当前时刻时暂停，复用元素评论和区域标注 | Web、桌面预览 |
| R4 | 反馈携带时间、来源、位置及当前画面截图 | Web、服务端、CLI |
| R5 | 从历史评论回到参考时间，提示来源发生变化 | Web、服务端、CLI |

首版针对带可靠时间轴的可编辑 Motion HTML。普通网页不出现播放器；交互型动效保留原交互。MP4 继续使用现有视频播放器，统一视频批注与真实解码逐帧留到下一步。不新增多轨剪辑、关键帧编辑、区间评论或对象跟踪。

这里的“帧”是 Motion 输出帧率对应的时间采样点。只有作品明确提供有效帧率时才展示帧数与逐帧按钮；不能假定所有作品都是 30fps。

以下是基于 main `9724c44142` 的源码核查，并非线上验收结论。

| 环节 | 已有能力 | 本次增加 |
| --- | --- | --- |
| Motion 播放 | 注册时间轴、播放暂停、定位、音轨同步 | 预览区可发现的控制栏与可靠状态反馈 |

## 用户流程

1. 打开已生成的 Motion HTML，预览下方出现播放器。拖动时间轴或输入秒数，画面停在相应时刻。
2. 点击“标注此刻”，系统确认已暂停，再开启现有标注入口。用户点选元素或使用区域标注，并填写修改要求。
3. 系统保存该时刻的时间、原画面和来源。用户可取消，也可沿用现有“保存评论／加入对话”操作。
4. 用户发送对话后，Agent 收到定位信息、图片和文字。时间点用于指出对象，修改影响哪些时段仍以用户要求为准。
5. 点击已保存的时间点评论，预览暂停并返回该参考时间；正常播放隐藏空间标记。

## 详细规则

### R1、R2：播放与精确定位

- 提供播放／暂停、重播、拖动定位与秒数输入，显示当前时间和总时长。
- 定位后停在新位置；用户明确播放后再继续。输入超出范围时限制到作品首尾，非法输入不改变画面。
- 已知帧率时，一次前后移动一个输出采样帧；未知帧率时以 0.1 秒微调，并明确标注单位。
- 拖动、输入与步进都以播放器确认后的时间显示。未连接或时间轴无效时，不开放标注，提示重新加载或检查作品。
- 进入评论或绘制标注时自动暂停。存在未完成标注时禁止播放与定位，避免标记与截图对应不同画面；退出标注后由用户决定继续播放。

### R3、R4：标注与反馈

- 元素评论复用现有点选；区域标注复用现有绘制入口。支持只针对当前画面留言，不强制选元素。
- 当前时刻反馈至少包含：文件来源、参考秒数、总时长、帧率（若已知）、来源指纹、标注位置和用户文字。来源指纹用于识别作品内容是否发生变化，不作为可恢复的历史版本承诺。
- 保存或加入对话前采集当前暂停画面，图片与反馈同一次操作绑定；不能改用重新打开作品时的首帧或旧截图。
- 截图失败时告知原因，保留文字与选区，允许重试；不得自动提交缺图的时间点评论。
- 保存失败保留草稿。取消不启动模型；仅沿用现有发送动作启动修改。
- 时间信息与图片只承担定位作用，不保证模型修改成功，也不自动把修改限制在单帧。

### R5：回看与变化

- 时间点评论展示可识别的时间标签。点击时先暂停，再定位到该参考时间，随后显示对应标记。
- 作品内容变化时保留原评论和原截图，提示“基于先前内容”；参考时间仍可定位到当前作品的有效范围，但旧位置不应被当作当前元素的准确位置。
- 切换文件、重新加载、切换预览传输方式后，必须重新确认当前播放器；上一文档迟到的状态或截图不能归到新文件。
- 评论字段向后兼容；历史普通评论没有时间信息时，沿用现有行为。

## 数据埋点

本次为本地首版验证，不新增遥测上报，沿用现有预览工具点击、评论和对话记录。采用率及定向修改效果的正式统计口径留在发布前确定，不用本地点击数推断效果。验收依靠真实保存的评论、截图和进入对话的结构化上下文；不记录截图内容到遥测。

## 验收标准

| 编号 | 对应需求 | 操作 | 可观察结果 |
| --- | --- | --- | --- |
| A1 | R1 | 8 秒作品定位到 2.4 秒 | 时间显示与画面一致，画面停止；播放后从该处继续 |
| A2 | R2 | 30fps 作品连续前进三帧 | 时间累计前进 0.1 秒；未知帧率时显示 0.1 秒微调 |
| A3 | R3 | 在移动标题出现时进入评论 | 标题保持原位置，播放和定位暂不可用；退出后可继续 |
| A4 | R4 | 选标题，填写要求，保存并加入对话 | 评论回读与 Agent 输入都包含参考时间、来源、选区和当前截图 |
| A5 | R4 | 截图失败后重试 | 草稿保留，不产生缺图的时间点评论；重试成功后可保存 |
| A6 | R5 | 点击历史时间点评论 | 暂停并回到对应参考时刻；播放时不显示旧空间标记 |
| A7 | R5 | 作品更新后查看旧反馈 | 原截图仍可看，提示来源已变化，不把旧位置冒充当前准确锚点 |
| A8 | R4、R5 | 截图中切换文件／重载 | 迟到结果不会附到新文件；旧的普通评论流程可用 |
| A9 | R4 | CLI 写入／读取时间点评论 | 与界面使用相同评论数据，可提供长文本文件并输出 JSON |
